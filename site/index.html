Config drift detector for Next.js + TypeScript

Every process.env,
accounted for.

EnvSync reads your source code, your envsync.config.ts contract and your .env.example, then tells you exactly where they disagree, with file, line and a fix. It runs locally, never executes your code, and never reads a secret value.

Quick start

Pre-release · v0.0.0 · Apache-2.0 · not yet on npm

01 · The model

Three files should agree. Usually they don't.

Variables get added in code and forgotten in the docs. Declarations outlive the features that used them. EnvSync treats each file as a different kind of evidence and checks them against each other.

  1. Source reads it

    Every process.env.NAME, ["NAME"] and destructured read, found by parsing the TypeScript AST. Nothing is imported or run.

    evidence

  2. envsync.config.ts declares it

    The contract: which variables exist, which are required, which are secret. Read as data, so it can't mean one thing at runtime and another to EnvSync.

    intent

  3. .env.example documents it

    What a new teammate copies on day one. Placeholders only. EnvSync uses the names and throws the values away.

    documentation

A missing declaration is not the same as a missing runtime value. EnvSync never claims to know what's in your real environment.

02 · The guarantee

Names go in. Values never leave the room.

Your real .env files are never opened. Values in .env.example are discarded as they're read. The output, terminal or JSON, only ever contains names and locations.

  • No values

    Never prints, stores or copies a value. .env / .env.* are never read.

  • Parsed, never run

    Source, next.config.* and the config are parsed into an AST. Nothing is imported or executed.

  • No network

    The scan makes no network requests. It works offline, on a plane, behind an air gap.

  • No surprise writes

    init previews by default. Only --write writes, and it never overwrites a file.

03 · The boundary

Secrets don't cross into the browser bundle.

Next.js inlines NEXT_PUBLIC_* variables and next.config env entries into client JavaScript. Declare a variable secret: true and EnvSync stops it at the border. Names that merely look secret get a warning, not a verdict.

04 · The table

Seven kinds of drift. Each one has a stable code.

Every finding comes with a code, a severity, the file and line, and a suggested fix. Codes are a public contract, so your CI can rely on them. Pick one to see real output.

05 · The output

Quiet, precise, and the same in CI.

Real output from the repository's test fixtures, unedited. Human-readable in the terminal, stable JSON for automation, and exit codes you can build on.

06 · Quick start

        
Five minutes from clone to first scan.

        
EnvSync isn't published to npm yet. Until the first release, run it from source. You need
           Node.js 22.12+ and pnpm 12.10.1.

      


      
    
        
  1. 
          
    1
    
          
    
            
    Clone and build
    
            
    
              
    git clone https://github.com/ABK1-Kuul/ENVSync.git
cd ENVSync
npm install --global pnpm@12.10.1
pnpm install
pnpm build
    
              
            
    
          
    
        
    2. 
        
  2. 
          
    2
    
          
    
            
    Preview a starter contract
    
            
    Lists every variable your code reads statically. Nothing is written yet.
    
            
    
              
    node apps/cli/dist/bin.js init path/to/next-app
    
              
            
    
          
    
        
    3. 
        
  3. 
          
    3
    
          
    
            
    Write it, then make it yours
    
            
    Creates envsync.config.ts and .env.example with empty placeholders. Existing files are never overwritten.
               Then mark what's secret and what's optional.
    
            
    
              
    node apps/cli/dist/bin.js init path/to/next-app --write
    
              
            
    
            
    
              envsync.config.ts
              
    export default {
  variables: {
    DATABASE_URL: { required: true, secret: true, type: "url" },
    NEXT_PUBLIC_SITE_URL: { secret: false, type: "url" },
    SENTRY_RELEASE: { required: false, external: true },
  },
};
    
            
    
          
    
        
    4. 
        
  4. 
          
    4
    
          
    
            
    Scan
    
            
    Run it whenever you touch config. Check your local setup with doctor, which also catches .env.local files that git doesn't ignore.
    
            
    
              
    node apps/cli/dist/bin.js scan path/to/next-app
node apps/cli/dist/bin.js doctor path/to/next-app

    Gate CI

    node apps/cli/dist/bin.js scan path/to/next-app --strict --format json
