# Plan a sprint

1. Read `PRODUCT.md`, `ROADMAP.md`, `ARCHITECTURE.md` and current git state.
2. Inspect actual implementation and tests; mark completed, partial and missing work based on evidence.
3. Prioritize by user value, risk reduction and dependency order.
4. Break work into small vertical slices with acceptance criteria and tests.
5. Identify security/privacy implications and explicit non-goals.
6. Avoid speculative infrastructure and features outside MVP.
7. Return a ranked backlog, dependencies, risk notes and a clear first task. Do not edit code unless asked.
